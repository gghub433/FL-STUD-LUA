# Stepwise DAW: архитектура

Браузерная DAW с паттерновым процессом работы (Channel Rack → Playlist), собственная тёмная тема, без чужих брендов и ассетов.
Стек: JavaScript (ES-модули), Web Audio + **AudioWorklet**, Canvas/DOM. Без фреймворков, без обязательной сборки.

```
npm start            # dev-сервер на http://localhost:8080
npm test             # unit-тесты движка и форматов (node:test)
npm run test:e2e     # сквозные тесты в Chromium: UI + реальный звук из AudioWorklet
npm run build        # dist/ (esbuild): один бандл + worklet
```

## 1. Слои

```
┌───────────────────────────── main thread ─────────────────────────────┐
│ ui/        окна, меню, тулбар, Channel Rack, Piano Roll, Playlist,    │
│            Mixer, Browser, редакторы плагинов (DOM + Canvas)          │
│ app/       store: проект (JSON), undo/redo, шина событий, команды     │
│ host/      AudioHost (AudioContext + worklet-нода + протокол),        │
│            SampleBank (decode/IndexedDB), Recorder, WebMIDI, экспорт  │
└───────────────┬───────────────────────────────────────────────────────┘
                │ postMessage (команды, патчи проекта, сэмплы) ▲ state/peaks/rec
┌───────────────▼─────────────────── audio thread ──────────────────────┐
│ worklet/processor.js  → core/engine.js (тот же код, что и офлайн)     │
└───────────────────────────────────────────────────────────────────────┘
        core/ — чистый JS без DOM и Web Audio. Один код для:
        AudioWorklet (live) · Worker/Node (offline render, экспорт, стемы) · unit-тесты
```

**Правило:** всё, что влияет на звук, живёт в `core/`. UI не знает DSP, движок не знает DOM. Поэтому экспорт в WAV даёт ровно то, что слышно в программе, а тесты проверяют реальный сигнал.

## 2. Планирование по сэмплам, а не по таймеру

Транспорт хранит позицию в **тиках** (`PPQ = 96`, шаг 1/16 = 24 тика). Для каждого блока в 128 фреймов `Engine._collect`:

1. считает `ticksPerSample = tempo·PPQ / (60·sampleRate)`;
2. идёт по скомпилированному отсортированному массиву событий курсором и переводит `tick → sampleOffset = ceil((t − tick0)/tps)`;
3. на границе loop-региона делит блок на сегменты, перенос `overshoot` сохраняется (loop не «уплывает» ни на сэмпл);
4. метроном и count-in вставляют события в тот же список;
5. инструменты рендерятся **срезами** между событиями (`inst.process(L, R, from, to)`), поэтому нота стартует на точный сэмпл.

Ни `setTimeout`, ни `requestAnimationFrame`, ни задержка `postMessage` на тайминг не влияют. Тест `step timing is sample accurate` проверяет отклонение ≤ 80 сэмплов от идеала с учётом атаки самого семпла.

Компиляция (`core/sequencer.js`): паттерн или плейлист разворачивается в плоский список `{t, kind, ch, key, vel, pan, rel, fine, mx, my, slide, len}`. Свинг применяется при компиляции, повторы паттерна внутри клипа разворачиваются, обрезка по границам клипа тоже. Правка проекта помечает `dirty`, перекомпиляция идёт в начале следующего блока, курсор бинарным поиском встаёт на текущий тик (звучащие ноты не перезапускаются).

## 3. Модель проекта (`core/project.js`)

Один JSON-объект, authoritative-копия в main thread, зеркало в worklet:

```
{ format:'stepwise', version, meta, seq (счётчик id), tempo, swing, masterPitch, timeSig, settings,
  channels:[{ id, type, name, color, enabled, vol, pan, pitch, mixer, group, params:{…}, sample?, … }],
  patterns:{ [id]:{ id, name, len, notes:{ [chId]:[{ id, s, l, k, v, pan?, rel?, fine?, mx?, my?, c?, slide? }] } } },
  playlist:{ arrangements:[{ id, name, tracks:{sparse}, clips:[{type,track,s,l,ref,o,…}], markers, loop, start, punch }], current },
  mixer:{ tracks:[126 × { vol, pan, sep, delay, eq*, mute, solo, arm, routes:[[dest,level,sc]], fx:[10 × slot|null] }] },
  samples:{ id → метаданные }, controllers:[MIDI-связки], groups }
```

* Время везде в тиках (целые). Необязательные поля нот не пишутся, пока равны значению по умолчанию (дешёвые undo-снимки).
* Сэмплы (PCM) **не** хранятся в JSON: они в `SampleBank` (IndexedDB), в проекте только ссылки.
* `normalize(raw)` валидирует и чинит всё, что приходит из файла/IndexedDB/zip (диапазоны, дубли id, циклы маршрутизации); идемпотентна.

### Адреса параметров (`core/addr.js`)

Каждая ручка проекта имеет строковый адрес: `ch:12:vol`, `ch:12:p:cutoff`, `mx:5:vol`, `mx:5:fx:2:p:threshold`, `mx:5:fx:2:mix`, `master:vol`, `transport:tempo`. Один адрес даёт: значение и схему (`paramDef`), запись (`setParam`), автоматизацию, MIDI-привязку, пункт «Create automation clip». Схема параметров (`core/schema.js`: диапазон, кривая lin/log/pow, enum, единицы, формат, разбор введённого текста) — единственный источник правды для движка, UI и автоматизации (клипы хранят нормализованные 0..1).

## 4. Аудиограф

```
Channel (Sampler/FPC/Slicer/Synth/FM/Drums/AudioClip/Layer)
   └ срезы между событиями → буфер канала → vol/pan (рампа) → Mixer.feed(trackN)

Mixer: inserts 1..125 + Master(0), топологический порядок (источники → приёмники)
   input bus ─ delay ─ [fx1…fx10, dry/wet] ─ 3-band EQ ─ separation ─ pan/fader ─ meter ─ routes
   routes: [dest, level, sidechain?] — любой трек в любой нижестоящий; sidechain доставляется на отдельную шину
   пустые треки без «хвоста» пропускаются (125 инсертов дёшевы)
   solo: сам трек + его потребители вниз до мастера + его источники вверх
Master → [метроном] → output
```

Метки: пики на каждом треке считаются в движке, воркллет шлёт их ~60 Гц вместе с позицией транспорта (`state`). Нагрузка CPU оценивается по `Date.now()` с усреднением (миллисекундное разрешение даёт несмещённую оценку при суммировании по многим блокам).

## 5. Протокол main ⇄ worklet

Главный → worklet: `init(project)`, `set(path, value)` (патч секции проекта: `['patterns', 3]`, `['channels']`, `['mixer','tracks',5]`…), `param(addr, value)` (ручки; не пересобирают ничего), `sample(id, rate, channels[])` (transferable), `play/stop/pause/seek/record`, `noteOn/noteOff`, `panic`.
Worklet → главный: `state{tick, playing, peaks, cpu}`, `rec` (метки нот при записи, тик в момент обработки), `wrap`, `ended`, `auto` (значения, которые меняет автоматизация, чтобы ручки двигались), `error`.

Запись нот: клавиша попадает в worklet, он ставит на ноту тик транспорта в момент обработки и возвращает `rec`, так что записанная нота совпадает с тем, что прозвучало.

## 6. Офлайн-рендер и экспорт

`core/offline.js` создаёт `Engine` без аудио-устройства, гоняет блоки до конца песни, затем `tail` (секунды или `auto` до тишины). Стемы по трекам: рендер с `solo` на каждом треке. Форматы: WAV 16/24/32f (TPDF-дизеринг), FLAC, OGG(Opus), MP3, MIDI, zipped project (см. `host/export`).

## 7. UI

* **Окна** (`ui/window-manager.js`): плавающие внутри контейнера: перенос, 8 ресайз-ручек, сворачивание, разворачивание, прилипание к краям, z-порядок, раскладка в `localStorage`.
* **Тулбар**: перетаскиваемые секции (порядок запоминается), двойной дисплей времени, темп, tap, метроном, count-in, overdub, blend, мастер, селектор паттерна, кнопки окон, осциллограф/спектр (`AnalyserNode`), CPU.
* **Ручка** (`ui/knob.js`): вертикальный драг, Ctrl — точно, двойной клик — ввод числа, ПКМ — меню параметра (автоматизация, MIDI-привязка, сброс). Привязана к адресу, подписана на изменения.
* **Hint bar**: по `data-hint` у любого элемента.
* **Undo**: снимки проекта с объединением непрерывных правок (драг ручки = одна запись), список истории в меню Edit.

## 8. Тесты

* `tests/unit/*.test.js` (node:test): точность тайминга, loop, соло/мьют/маршрутизация, автоматизация, нормализация, форматы экспорта (проверка сторонним декодером).
* `tests/e2e/` (Playwright + Chromium): запуск приложения, реальные клики, проверка, что AudioWorklet выдаёт сигнал (пики приходят из движка), скриншоты.

## 9. Что намеренно не копируется

Название, логотип, шрифты, значки, звуковые библиотеки и код Image-Line. Раскладка и рабочий процесс повторяют общепринятую идиому «паттерны → плейлист», визуальный стиль собственный.
